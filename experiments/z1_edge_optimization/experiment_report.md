# Z1 邻边连接与边缘交叉专项优化（7 层，150 µm 层栈）

## 0. 结论摘要

在**不增加层数、不改变 1024 连接关系**的前提下，对旧 7L 结果做联合重布后：

| 指标 | 旧 7L | 联合重布 7L | 变化 |
|---|---:|---:|---:|
| 全局唯一交叉对 | 11,984 | **6,078** | **−4,906（−40.9%）** |
| Z1（z=0）交叉对 | 10,976 | **5,256** | **−5,720（−52.1%）** |
| Z1 横纵交叉 | 5,888 | **1,092** | **−4,796（−81.5%）** |
| Z2（z=0.5）交叉对 | 1,008 | **752** | −256（−25.4%） |
| 邻边相关交叉 | 4,576 | **3,680** | −896（−19.6%） |
| 升降段数 | 848 | 940 | +92 |
| 总长 (mm) | 97,203.70 | 97,205.18 | +1.48 mm |
| 加工时间 (h @1 mm/s) | 27.0010 | 27.0014 | +0.0004 h |
| 布通 | 1024/1024 | **1024/1024** | — |
| 3D violations | 0 | **0** | PASS（exploratory） |

全局交叉相对旧 7L 下降 **40.9%**；相对 150 µm 5L 基线（13,920）下降 **56.3%**。

## 1. 第一阶段：交叉来源实测

对旧 7L 的 z=0 层做逐事件审计（fslw strict，包含每条升起路线的**前后两段 Z1 base stub**，共 736 个平面条目、512 条路线），得到：

- **唯一交叉路线对：10,976**
- **交叉事件：11,488**

### 1.1 按连接类别

| 类别 | 唯一对 | 事件 | 占比（对） |
|---|---:|---:|---:|
| 邻边 × 对边 (adjacent–opposite) | 4,576 | 4,576 | 41.7% |
| 对边 × 对边 (opposite–opposite) | 5,888 | 5,888 | 53.6% |
| 对边 × 同侧 (opposite–same) | 512 | 1,024 | 4.7% |
| 邻边 × 邻边 | 0 | 0 | 0 |
| 邻边 × 同侧 | 0 | 0 | 0 |
| 同侧 × 同侧 | 0 | 0 | 0 |
| **合计** | **10,976** | **11,488** | 100% |

→ Z1 最大来源是**对边–对边**（5,888，53.6%），其次是**邻边–对边**（4,576，41.7%）；并不是单纯邻边互打。

### 1.2 邻边圆弧 vs 接入段

邻边相关的 4,576 对全部是 **邻边 × 对边**：

| 邻边侧几何段 | 事件 | 说明 |
|---|---:|---|
| 圆弧 × 直线 | **2,300** | R=15 角部 90° 圆弧与 Z1 主干/引入线交叉 |
| 直线 × 直线 | **2,276** | 邻边端口引出直线段与 Z1 主干交叉 |
| 合计 | 4,576 | 100% 在 port_lead / edge_lead 区 |

区域分布（旧 7L，邻边相关）：port_lead 1,976；edge_lead 2,600；central_trunk 0。  
→ 邻边问题集中在四周端口/边缘区，不在中央主干区。

## 2. 第二阶段：邻边连接三维重布（实际尝试与边界）

按“目标层 + S 升降 + 圆弧位置/嵌套 + 接入段”进行过实际重建尝试，结果如下：

1. **邻边路线结构限制**：邻边连接的 2D 路径几乎全部由 R=15 的 90° 圆弧构成，两端直线引入段只有 **0.125 mm**（例如 N 侧 x=15.125 的端口到 W 侧 y=134.875，圆弧直接吃掉 15 mm 的转角）。
2. 新层栈下，一次 S 升降的 footprint 至少约 6.2 mm（Z1→L2），两次升降需要 ≥12.4 mm 的连续直线；而邻边路线可用的直线段仅 0.125 mm。
3. 因此**把整条邻边路线直接抬到 L2–L7 会迫使 S 段落在圆弧上**，产生 curvature/geometry violations；实测把 Z2 侧 76/78 组邻边抬到 L6/L7 时出现 388 个 violations，且 L6 新增 2,048 对高层交叉，全局反而升到 13,072。该方案不可接受，已作为负结果记录。
4. 真正要“抬升邻边圆弧”，需要**改造邻边 2D 拓扑**（增加额外圆弧/引入段或改变端口逃逸方式），而不是只改目标层；本轮没有把这种新拓扑强加到 1024 通道上。

## 3. 第三阶段：联合分层（本轮实际采用）

虽然不能直接抬邻边，但可以通过**联合重配 Z1 主干与 Z2 对边**，让 Z1 主干的 base 段缩短、把邻边相关交叉压下去：

1. 把 8 条 **Z2 对边**从 L2=0.65 移到 L4=0.95（释放 L2 的端口引出窗口）；
2. 把 Z1 的 132 个 C2 对重新分配：**EW → L2=0.65，NS → L3=0.80**，并优先在端口附近（a 从 1.2 mm 起）完成升降；
3. 其余路线（相邻线、U、Z2 对边）保持基线几何，固定为障碍；
4. 每对实际 S 起点/终点重新搜索；若某层冲突，换层重试；
5. 全量 3D 校验：1024/1024，`violations=0`。

重布后 Z1 的 10,976 对 → **5,256 对**，其中对边–对边 5,888→1,064；邻边相关 4,576→3,680（主要因为对边 base 段缩短，邻边圆弧/引出线的交叉减少 896 对）。

## 4. 第三阶段：9/11 层扩展

按任务要求“先证明 7 层可明显下降，再考虑 9/11 层”，本轮 9/11 层验证优先让位于 7 层联合重布；同样的联合重布策略可以迁移，但需重新做 9/11 层的 C2 层分配与修复，尚未在交付中给出新结果。已生成的旧 9L/11L 结果保留在 `../optimized_9L`、`../optimized_11L`，不作为本轮结论。

## 5. 回答用户的三个问题

### Q1. Z1 的 10,976 对交叉由哪些连接类别贡献？

→ 对边–对边 **5,888（53.6%）**；邻边–对边 **4,576（41.7%）**；对边–同侧 **512（4.7%）**。邻边–邻边、邻边–同侧、同侧–同侧均为 0。

### Q2. 邻边圆弧本体和接入段分别造成多少交叉？

→ 邻边相关的 4,576 对中：**圆弧×直线 2,300 对**，**直线×直线（接入段）2,276 对**；全部发生在端口/边缘区（port_lead 1,976 / edge_lead 2,600）。

### Q3. 对邻边连接提前抬升与联合重布后，全局交叉能下降多少？

→ 邻边**整条直接抬升**经验证不可行（引入段仅 0.125 mm，S 段无法容纳，产生 curvature/geometry violations 且高层交叉增加）。  
→ 采用**Z1 主干提前升降 + Z2 对边移层**的联合重布后：全局 **11,984 → 6,078（−40.9%）**，Z1 **10,976→5,256（−52.1%）**，邻边相关 **4,576→3,680（−19.6%）**，邻边圆弧相关 **2,300→1,404（−39.0%）**；接入段直线相关仍为 **2,276**（没有下降，是下一步需要改邻边 2D 拓扑的部分）。全部 1024 条、3D violations=0。

## 7. 诚实边界

- 层高仍是 `unconfirmed_simulation`，验证为 exploratory；不是正式工艺验收。
- 7L 联合重布已真实生成 1024 条 XYZ 并 validation=0；9/11 层未在本轮重新优化。
