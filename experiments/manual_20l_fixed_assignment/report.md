## 2. Z1 人工 U：256 条重新构造并真实抬升到 L2–L5

映射规则（只改变物理目标层，不改变端口配对/人工组/嵌套顺序）：

| 旧层（640 CSV） | 新层 | 数量 |
|---|---|---:|
| L1 | L2（z=0.65） | 64 |
| L2 | L3（z=0.80） | 64 |
| L3 | L4（z=0.95） | 64 |
| L4 | L5（z=1.10） | 64 |

实现不是“改 CSV 层号”，也不是给旧 z 加常数：

1. 从 `z1_z2_manual_u_assignment_v2_640.csv` 恢复 256 条 `manual_fixed_u` 的端点、`manual_group`、`manual_group_order`、`u_pair` 和源侧。
2. 用 `manual_u_geometry.build_manual_u_geometry` 重新构造每一条 R15 嵌套 U；臂长按目标层过渡足迹重新计算；对嵌套 U 保留“外层更深、内层更浅”的链式关系。
3. 对每条 U 在直臂上重新放置 **上升 S 段 + 目标层直臂/底部 + 下降 S 段**；端点仍为 Z1 真实端口 z=0。
4. 每条候选都经过真实三维 world 检查（同层 D56 + 跨层 3D 净空 + 端口 keep-out），只有合法才加入已布通集合。
5. L6 不生成任何新线路。

结果：**256/256 条人工 U 全部位于 L2–L5，每层 64 条；Z1 接口没有留下完整 U 主体，只保留端点引出和 S 段起止。** 这 256 条全部通过真实三维验证器。

- 人工 U 路径长度：min 74.06 mm / mean 108.13 mm / max 173.31 mm。
- 每条人工 U 都有 2 个 S 形升降段，共 512 个人工 U 过渡段。
- L2 的人工 U 不再是平面 U：64 条全部新增真实上升/下降段。

## 3. Z1 相对边连接：L7 / L8

从原始 512 条 Z1 中按 `relation=opposite` 筛选：

- N→S / S→N：128 条，指定 **L7（z=1.40）**。
- E→W / W→E：128 条，指定 **L8（z=1.55）**。

每条线路的形式是：

`Z1 真实端口 z=0 → 引出直段 → R15 S 形上升 → L7/L8 主体 → R15 S 形下降 → Z1 真实端口 z=0`

实现上不是仅修改 `assigned_layer`：`fixed_layer_3d` 用真实 S 曲线、真实目标 z 和真实长度重新组装 route parts；平层主体确实在 L7/L8，端点高度确实回到 0。

实际结果：

| 目标 | 分配 | 实际完成 | 说明 |
|---|---:|---:|---|
| L7 南北 128 | 128 | **127** | 1 条失败（route 143） |
| L8 东西 128 | 128 | **128** | 全部完成 |

**Route 143 失败原因：** 该线的 2D 冻结路径含有两段近端口 R15 圆弧，唯一足够长的直段只能容纳“上升+下降”中的一段；所有 75 个窗口候选与 200 条 2D 重规划候选都至少与一条已固定的 Z1 过渡/人工 U 在 0.08 mm 内冲突。按任务纪律，没有放宽 R15/净空，也没有伪造为成功。它是唯一一条未布通的 Z1 线路。

## 9. 主要物理瓶颈：为什么 Z2 只完成 162/444、接口 0/68

这是本轮最重要的工程结论。

### 9.1 端口共轨 + z=0.5 平面穿越

Z1 和 Z2 的两个接口 row 在端口模型里共享同一 XY（`N01:1:c` 与 `N01:2:c` 的 routing_xy 相同，只差 0.5 mm 高度）。因此每一条 Z1 线路从 z=0 抬升时，必须在某个水平位置穿过 z=0.5 平面；而同一端口的 Z2 线路正好从 z=0.5 出发。如果两条线路在端口附近共用同一段近端口引出轨道，Z1 的 S 曲线在离端口约 3.5–4.2 mm 处就到达 z=0.5，而 R15 使 Z2 在同一距离内最多横向让开约 0.4 mm。是否满足 0.08 mm 净空，取决于冻结 2D 路径是否在端口处立刻转弯。

实测：

- 48 条有 2D 几何的 Z2 接口线路，在空的 z=0.5 平面上 **48/48 都能放下**（说明接口平面本身不拥挤）。
- 加入完整 511 条固定 Z1 世界后，**0/48 能通过**；失败全部是 `flat_vs_transition`，最近距离 0.02–0.07 mm（很多只差不到 0.06 mm）。
- 270 条高层 Z2 失败中，绝大多数是 `no_legal_plan`：冻结 2D 路径的 .5 引出段与 Z1 过渡冲突，或者上升/下降窗口与 L7/L8 的 128 条竖/横线幕冲突。

### 9.2 顺序依赖性（独立复现实验）

独立子实验（`scratch/team_z2/REPORT.md`）在同一个 C5R4 Z1 世界快照上测试：

| 构建顺序 | 子集 | 成功率 |
|---|---|---:|
| Z1 固定后，再放 Z2 | 前 40 条 adjacent | 28/40（70%） |
| Z1 固定后，再放 Z2 | 60 条 same-side | 38/60（63%） |
| 同样的世界，库存 `transition_plans` 搜索 | 前 40 条 adjacent | 12/40（30%） |
| 只有 256 条人工 U、无 L7/L8 的 Z1 世界 | 前 40 条 adjacent | **39/40（97.5%）** |

**这说明顺序和联合布局比单条路径搜索更重要**：Z2 先布、Z1 后布时，Z2 端口可以自由选择逃逸方向；Z1 先布并占满 L7/L8 后，Z2 的 z=0.5 引出段几乎没有合法的 R15 逃逸空间。

### 9.3 硬上限

- 444 条高层 Z2 中有 **12 条原始 2D campaign 本身就没有几何**（621–624、629–632、853–856），在“不重新做完整 2D 布线”的纪律下，最大可布通 432/444。
- 68 条 Z2 接口线路中 20 条原始 2D 也未布通，最大 48/68。
- 独立实验估计：若 Z1 先布，placement search 的上限约 300/444；若 Z2 先布、Z1 最后重建，约 410/432。本轮固定顺序达到 162/444，低于该上限，原因是本轮使用了冻结 2D 路径 + 固定层窗口，而不是联合重排 Z1 过渡起点。

### 9.4 当前失败分类

| 失败原因 | 条数 |
|---|---:|
| Z2 高层：固定 Z1 世界下无合法过渡/路径计划 | 270 |
| Z2 高层：原始 2D campaign 无几何 | 32 |
| Z2 接口：与 Z1 过渡在 z=0.5 真实三维冲突 | 48 |
| Z1：route 143 无合法窗口（唯一 Z1 失败） | 1 |

## 13. 局限与下一步建议

1. **本轮不是“全部 1024 成功”**。673/1024 是真实、可复现、0 几何违规的结果；351 条失败均记录了原因，没有用降低净空/R15 或回退接口层伪造成功。
2. **交叉数低不能单独作为改善证据**：成功集合从 992 降到 673。公平的共同集结果（673 条共同线路：旧 52104 → 新 4357）支持“高分层可显著减少平面交叉”，但必须同时报告成功率下降。
3. **真正的瓶颈是 Z1/Z2 共端口轨道与 z=0.5 平面穿越**。下一步应做的是**顺序/联合重布**，而不是继续在固定 Z1 世界后搜索：先把 Z2 接口与高层线路放在 z=0.5 上、并允许 Z1 过渡起点重排；或者对每个端口对（z1 row / z2 row）建立共用的“逃逸走廊”约束，再同时放置两层。
4. 12 条 Z2 高层线路在原始 2D campaign 中无几何；要突破 432/444 必须做真正的 2D 重规划，这超出本轮“固定人工分组/端点、复用现有 2D 路径”的纪律。
5. L7/L8 全部相对边放在同一平面会自然产生大量合法平面交叉（约 1.6 万对候选，最终 1575/1586 对）。若目标是降低全局交叉，应把部分相对边拆分到不同层，而不是全部压到 L7/L8；本轮严格服从了人工指定层号。
