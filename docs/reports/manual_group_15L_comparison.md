## 2. 人工分组实际执行情况（必须如实说明）

| 项 | 数值 |
|---|---:|
| 明确标记且层号 L1–L4 的人工记录 | 256（L1 64 / L2 64 / L3 64 / L4 64） |
| 实际在人工层执行 | **16 条**（全部为 L4 抬升成功）；L1 的 64 条本身就在接口层平面（无需抬升） |
| 人工层抬升失败（保留在接口层平面） | **176 条** |
| 失败原因 | `no_transition_window` 108（2D 路径的直线臂长不足 R=15 mm 抬升 S 曲线 + 安全区）；`world:transition_vs_flat` 68（抬升 S 曲线与 z2 接口平面 z=0.5 mm 上的波导真实三维净空冲突） |
| 人工组（C4 组，禁止旧算法改动） | 64 |

**结论（如实）**：在现有冻结 2D 布局上，人工 L1–L4 分组只能部分执行（16/192 条抬升成功；L1 的 64 条为平面保持）。原因有两类物理约束：(a) 现有 2D 布局中同侧 U 型路径的直线臂较短，放不下 6.2–6.5 mm 的 R15 抬升 S 曲线；(b) z1 线路抬升时必然穿过 Z2 接口平面（z=0.5 mm），而该平面在相同接头列上有 z2 波导，净空不足。这是真实几何约束，未通过放宽 R15/净空或伪造布通来规避。

**交叉下降的归因**：-1168 对并非全部来自这 16 条人工抬升；主要来自"64 个人工组被冻结、旧算法将其抬升预算改分配到其它组"（旧算法本次抬升 51 组、220 条，基线 48 组、192 条，其中 z1 opposite 组 14 个 vs 基线 2 个）。因此本次结果应理解为：**该人工分组方案在现有 2D 布局下的可执行部分 + 旧算法的总交叉**，而不是人工分组单独带来的优化幅度。

## 4. 验证

- 冻结验证器（R=15、中心线净空、同层 strict、跨层三维、自净空）：**violations = 0**，`geometry_pass = True`，`exploratory_pass = True`。
- 唯一状态说明：冻结验证器的层栈 schema 白名单只认 L2–L5，因此 15 层栈被标为 `invalid_stack`（这是层栈 schema 记账限制，不是几何违规；几何检查已执行且全部为 0）。基线 15L 的历史产物有同样的 15 层记账问题（其 payload 中只声明了 1–5 层）。
- 合法设计交叉不计为违规；本报告的所有交叉均为几何设计交叉。

## 5. 结论

1. 人工分组与旧算法可以在同一 1024 通道数据上串行执行：人工组优先占用 L1–L4，其余由旧算法从 L5 起分配，未修改任何连接关系。
2. 在现有冻结 2D 布局上，人工 L1–L4 只能部分落地（16/192 条抬升成功，L1 保持 64 条）；**176 条人工抬升受真实几何约束失败**。
3. 总交叉 74,626 对，相比基线 75,794 对减少 1,168 对（-1.54%）；该差异主要来自人工组冻结后旧算法的层分配变化，人工抬升本身贡献有限。
4. 若要让人工 L1–L4 真正全部执行，需要（不属于本轮范围）：重布 2D 布局使 U 型直线臂加长、或把人工作为 2D 约束、或让同列 z2 波导先抬离 z=0.5 平面。
